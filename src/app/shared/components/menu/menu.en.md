# Menu (`app-menu`)

A list of **actions** that opens from a button (WAI-ARIA *menu button* pattern). The button gets `[appMenuTrigger]`, and the items are **native** `<button>` and `<a>` with `appMenuItem`: your `(click)`, `routerLink`, `href` and icons work as usual. It opens next to the button with `position: fixed` (not clipped by `overflow`) and flips up when there is no room.

- **Files:** `src/app/shared/components/menu/` (import `MENU_IMPORTS` from `menu/index.ts`)

| When to use | Component |
|---|---|
| Several **actions** behind a button ("Actions", "⋮") | **`app-menu`** |
| Picking a **value** that stays in the field | `app-select` |
| Moving between sections of the same screen | `app-tabs` |
| One or two visible actions | `appButton` directly |

## Why it exists

A "menu" built with `<div>`s and `*ngIf` usually fails keyboard and screen reader users: focus does not enter the list, arrows do nothing, Esc does not close it, focus is lost after choosing, and the panel gets clipped inside a scrolling table. This component follows the *menu button* pattern: focus managed by the arrows, type-to-find, Esc and Tab close it, focus goes back to the button, and the panel floats above everything.

## When to use

### Use when

- One item has several actions that do not all fit on screen, like "Edit, Duplicate, Archive, Delete" on a table row.
- The actions are secondary and would be heavy as loose buttons.

### Prefer another

- People pick a **value** that stays visible in the field: use the [Select](../select/select.en.md).
- One or two important actions: keep them as visible buttons ([Button](../button/button.en.md)); hiding the main action in a menu gets in the way.
- Switching sections on the same screen: use the [Tabs](../tabs/tabs.en.md).

## Usage

```ts
import { MENU_IMPORTS } from './shared/components/menu';

@Component({ imports: [...MENU_IMPORTS, ButtonDirective], ... })
```

```html
<button appButton variant="outline" [appMenuTrigger]="actions">Actions</button>
<app-menu #actions>
  <button appMenuItem (click)="edit()">Edit</button>
  <a appMenuItem routerLink="/orders/1042">Open the order</a>
  <button appMenuItem disabled>Move (no permission)</button>
  <hr appMenuSeparator>
  <button appMenuItem tone="danger" (click)="delete()">Delete</button>
</app-menu>

<!-- icon only: name the button; the menu is named by label -->
<button appButton variant="ghost" iconOnly aria-label="More actions for order 1042" [appMenuTrigger]="more">⋮</button>
<app-menu #more label="Actions for order 1042" placement="bottom-end">...</app-menu>
```

- **Choosing an item** closes the menu and returns focus to the button **before** the item's `(click)` runs. If the action opens a confirmation [Dialog](../dialog/dialog.en.md), it keeps the menu button and returns focus to it when it closes.
- **Disabled** (`disabled`): the item stays reachable with the arrows (so people know it exists), with `aria-disabled`, but does nothing. The native `disabled` is removed on purpose.
- **Placement** (`placement`): `bottom-start` (default), `bottom-end`, `top-start`, `top-end`. Without room it flips; a menu taller than the space scrolls.

## API

### `app-menu` · Inputs

| Prop        | Type            | Default          | Description |
|-------------|-----------------|------------------|-------------|
| `label`     | `string \| null` | `null`          | Menu name (`aria-label`). Without it, the menu is named by the button text (`aria-labelledby`). |
| `placement` | `MenuPlacement` | `'bottom-start'` | Preferred side and alignment: `bottom-start`, `bottom-end`, `top-start`, `top-end`. |

### `app-menu` · Outputs and methods

| Name           | Type / payload | Description |
|----------------|----------------|-------------|
| `openedChange` | `boolean`      | Opened (`true`) or closed (`false`). |
| `close()`      | method         | Closes it (returns focus to the button). Use with `#actions` in the template. |

### `[appMenuTrigger]`

| Input            | Type            | Description |
|------------------|-----------------|-------------|
| `appMenuTrigger` | `MenuComponent` | The menu the button opens (the `#actions` variable on `<app-menu>`). |

### `appMenuItem` (on `<button>` or `<a>`)

| Input      | Type                    | Default     | Description |
|------------|-------------------------|-------------|-------------|
| `disabled` | `boolean`               | `false`     | Reachable but inactive (`aria-disabled`). |
| `tone`     | `'default' \| 'danger'` | `'default'` | `danger` for destructive actions (red text). |

`appMenuSeparator` (on `<hr>`): a line between groups of items (`role="separator"`).

## Accessibility and keyboard

| Key | On the button | In the menu |
|---|---|---|
| `Enter` / `Space` | Opens on the first item | Chooses the item (`Space` on links too) |
| `↓` / `↑` | Opens on the first / last item | Next / previous (wraps) |
| `Home` / `End` | — | First / last item |
| Letters | — | Next item starting with the text (accent/case-insensitive) |
| `Esc` | Closes the menu, if open | Closes and goes back to the button (a Dialog behind does not close too) |
| `Tab` / `Shift+Tab` | — | Closes and moves on to the next / previous (with `Shift+Tab`, usually the button itself) |

- The button has `aria-haspopup="menu"`, `aria-expanded` and `aria-controls` (while open).
- `role="menu"` with a name (`label`, or the button text); `role="menuitem"` items out of the Tab order (the menu moves focus).
- Clicking outside closes it without taking focus; choosing an item returns focus to the button.
- Icon-only button: give it an `aria-label` (the Tooltip helps sighted users).

## Tokens

With defaults: `--menu-bg` (`--surface`), `--menu-fg` (`--fg`), `--menu-border` (`--border`), `--menu-shadow`, `--menu-item-hover` (an `--accent` tint). The `danger` item uses `--danger`; disabled, `--muted`; focus, `--accent`.
