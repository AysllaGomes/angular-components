# Checkbox group

> Default texts in **English**, replaceable in one place with [`provideUiLabels`](../../labels/labels.en.md) (`labels.*` in the tables below); each instance's input wins.

**Multiple** choice among visible options: the value is the list of what is checked. Built on **native** `<fieldset>` + `<legend>` and `<input type="checkbox">`, with the same box as the Checkbox (`app-checkbox-mark`, `--cb-*` tokens) and an optional "Select all".

- **File:** `src/app/shared/components/checkbox-group/checkbox-group.component.ts`
- **Model:** `src/app/shared/components/checkbox-group/checkbox-group.types.ts`

| When to use | Component |
|---|---|
| Several options at once, all visible | **`app-checkbox-group`** |
| A single option among a few | `app-radio-group` |
| A single yes/no (consent, confirmation) | `app-checkbox` |
| Many options in a tree, or little space | `app-tree-select` (`checkbox` mode) |

## Why it exists

A list of checkboxes looks simple, but the group needs a `<fieldset>` with a `<legend>`, a list value that does not depend on the click order, error and hint linked to every box, and forms integration; and "Select all" needs the partial state and must not touch disabled options. This component builds all of that from a list of options, with the same look as the Checkbox.

## When to use

### Use when

- People can check several options, or none, among a few (up to about 10).
- It helps to show every option at once, like notification preferences or permissions.

### Prefer another

- Only one option can be chosen: use the [Radio group](../radio/radio-group.en.md).
- A single yes/no, like accepting the terms: use the [Checkbox](../checkbox/checkbox.en.md).
- Many options, or groups within groups: use the [TreeSelect](../tree-select/tree-select.en.md) in `checkbox` mode.
- The change applies right away, like turning a setting on: use the [Switch](../switch/switch.en.md).

## Usage

```ts
topics: CheckboxOption<string>[] = [
  { label: 'News', value: 'news', description: 'Once a month' },
  { label: 'Deals', value: 'deals' },
  { label: 'Account security', value: 'security', disabled: true },
];
alerts = new FormControl<string[]>(['security'], { nonNullable: true, validators: Validators.required });
```

```html
<app-checkbox-group label="Email alerts" selectAll required
  [options]="topics" [formControl]="alerts"
  [error]="alerts.touched && alerts.invalid ? 'Choose at least one alert.' : null" />

<!-- without forms -->
<app-checkbox-group label="Interests" orientation="horizontal" [options]="interests" [(value)]="chosen" />
```

- The **value** is the list of checked `value`s, always **in the order of the options** (not the click order). A value that comes from outside and is not among the options is kept at the end, so saved data does not disappear.
- **Required:** `required` only shows the marker on the group label. Validate in the form: `Validators.required` already treats the empty list as invalid. (Native `required` on each box would demand checking **all** of them.)
- **Select all** (`selectAll`): checks the enabled options that are missing; if they are all checked, unchecks them all. It is **partial** while only some are checked. Disabled options stay as they are.

## Accessibility and keyboard

- `<fieldset>` + `<legend>`: screen readers announce the group name when entering it.
- **Native** checkboxes: `Tab` goes through each box (skipping disabled ones) and `Space` checks/unchecks; clicking the text checks too.
- "Select all" is a native checkbox with a **partial** state (`indeterminate`), announced as "partially checked", and points to the boxes it controls (`aria-controls`).
- Each option's `description`, the hint and the error are linked by `aria-describedby`; the error sets `aria-invalid` on each box.

## Tokens

The same as the Checkbox, with defaults: `--cb-size`, `--cb-border`, `--cb-bg`, `--cb-checked-bg`, `--cb-hover-ring`, `--cb-focus-ring`, `--cb-disabled-border`, `--cb-disabled-bg`. The error uses `--danger`.
