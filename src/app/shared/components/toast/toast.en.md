# Toast (Standalone, HTML + Sass)

> Default texts in **English**, changeable in one place with [`provideUiLabels`](../../labels/labels.en.md) (`labels.*` in the tables below); each instance's input wins.

A lightweight, accessible **toast** solution built from **service + container**. The **service** manages the queue (signals) and the **container** renders the stack. No UI framework.

---

## Why it exists

Messages that appear and go away have to be announced by screen readers without stealing focus, stack without overlapping, stay clickable even with a modal open and not rely on timers on the server (SSR). This component splits the queue (a service with signals) from the display (a container), so any part of the app calls `toast.success(...)`.

## When to use

### Use when

- Confirming that an action worked (saved, sent, copied).
- Warning about an error that does not block moving on.
- Offering a quick, optional action, like "Undo".

### Prefer another

- People must decide something before moving on: use the [Dialog](../dialog/dialog.en.md).
- A form field error: show it next to the field ([Forms](../../forms/forms.en.md)).
- Information that must stay on screen: use a fixed notice on the page, not a toast that goes away.

## API

### Types
```ts
export type ToastKind = 'success' | 'error' | 'info' | 'warning';

export interface Toast {
  id: number;
  kind: ToastKind;
  message: string;
  duration?: number;          // ms (0 = do not auto-dismiss)
  dismissible?: boolean;      // default: true
  actionLabel?: string;
  onAction?: () => void;
}
```

### Service (`ToastService`)
| Method | Returns | Description |
|---|---|---|
| `show(message, kind?, options?)` | `number` (id) | Shows a toast. `kind` defaults to `'info'`; `options` are the optional `Toast` fields (`duration` defaults to `4000` ms, `0` never closes on its own). |
| `success(message, options?)` | `number` | Shortcut for `show(message, 'success', options)`. |
| `error(message, options?)` | `number` | Shortcut for `show(message, 'error', options)`; announced with `role="alert"`. |
| `info(message, options?)` | `number` | Shortcut for `show(message, 'info', options)`. |
| `warning(message, options?)` | `number` | Shortcut for `show(message, 'warning', options)`. |
| `dismiss(id)` | `void` | Closes one toast by id. |
| `clear()` | `void` | Closes all of them. |

> **SSR-safe:** timers are created in the browser only.

### Container (`<app-toast-container>`)  
No `@Input()`s — reads `toast.toasts()` (signal) from the service and renders. Uses `role="status"` (polite) and `role="alert"` for errors.

## Usage

1) **Place the container** once (e.g., on Demo Page / App):
```html
<app-toast-container></app-toast-container>
```

2) **Inject & trigger** in your component:
```ts
import { Component, inject } from '@angular/core';
import { ToastService } from './toast.service';

@Component({ standalone: true, template: `
  <button (click)="ok()">Success</button>
  <button (click)="fail()">Error</button>
`})
export class Example {
  private toast = inject(ToastService);

  ok()   { this.toast.success('Request completed.'); }
  fail() { this.toast.error('Something went wrong.', { duration: 7000 }); }
  withAction() {
    this.toast.info('File is ready.', { actionLabel: 'Download', onAction: () => {/*...*/} });
  }
}
```

## Accessibility
- `aria-live="polite"` on the stack; `role="alert"` for errors (assertive).
- Close button with `aria-label="Close"`.
- Visible focus styles for action/close buttons.

---

## Tips
- Keep it until closed: `{ duration: 0 }`.
- Queue limit: service keeps a capped stack (e.g., 5 toasts).
- Action: `actionLabel` + `onAction()`; it closes after executing.

---

## Troubleshooting
- **Toasts don’t show**: missing `<app-toast-container>` in the DOM.
- **SSR timer issues**: make sure no extra `setTimeout` runs outside the service (which is SSR-safe).
