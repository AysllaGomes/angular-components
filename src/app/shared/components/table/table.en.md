# Table (Standalone, HTML + Sass)

> Default texts in **English**, changeable in one place with [`provideUiLabels`](../../labels/labels.en.md) (`labels.*` in the tables below); each instance's input wins.

A **customizable table** with optional row selection (checkbox), **actions column** (declarative via `[actions]` or via `appActions` slot), **chips**, and **custom cells** — all in **plain HTML + Sass** as a **standalone Angular** component.

---

## Why it exists

Data tables bring many needs together: selecting rows (across pages too), acting on one or many, sorting, paginating, telling people when it is loading, empty or failed, and staying readable on narrow screens. Built by hand, keyboard, screen reader and focus often come last. This table puts those features on a real `<table>`, with no library, and each one is optional.

## When to use

### Use when

- The data has rows and columns people compare or scan.
- People need to select rows and act on them, one by one or in bulk.
- The list is long: paginate in the browser or on the server.

### Prefer another

- A few items with nothing to compare across columns: a plain list (`<ul>`) is lighter.
- Picking an item to fill a field: use the [Select](../select/select.en.md).
- Picking from hierarchical data: use the [TreeSelect](../tree-select/tree-select.en.md).

## Collapsible columns

When the table gets wider than the available space, instead of scrolling horizontally it hides columns by `ColumnDef.priority`, and a **Mostrar detalhes** button on each row opens the hidden values.

```ts
columns: ColumnDef<Row>[] = [
  { key: 'nome',      header: 'Name' },                     // priority 1 (default): never hides
  { key: 'tipo',      header: 'Type', type: 'chip', priority: 2 },
  { key: 'documento', header: 'Document' },
  { key: 'limite',    header: 'Limit', priority: 3 },       // hides first
];
```

- **By the table width**, not the screen: the table measures its wrapper (the same as the paginated footer), so it also works inside a narrow card. The highest `priority` hides first (ties: the rightmost); when there is room again, they come back in reverse order.
- **Details:** the button (`aria-expanded`, `aria-controls`) opens a row right below with "Label: value" for the hidden columns, aligned with the first data column. Chips and custom cells (`appCell`) show as in the column.
- With no column above priority 1, nothing changes (the table scrolls as before). In card mode (≤ 640px) every field shows, so nothing collapses.
- On the server (SSR) every column renders; collapsing starts in the browser after the first measurement.
- Texts: `detailsLabel` (screen-reader name of the button column) and `expandLabel`.

## Pagination

With `paginate`, the table shows a footer with the range ("Mostrando 1–5 de 6"), the rows-per-page selector (with `pageSizeOptions`) and the pages ([`app-pagination`](../pagination/pagination.en.md)).

### Client (`paginate="client"`)

Pass **all** rows in `data`; the table shows the page slice.

```html
<app-table [columns]="columns" [data]="sortedRows()"
           paginate="client" [(pageIndex)]="page" [(pageSize)]="perPage"
           [pageSizeOptions]="[10, 25, 50]"
           [selectable]="true" rowKey="documento" />
```

- **Sorting** from the header goes back to the first page.
- If `data` **shrinks** (e.g. a delete on the last page) and the page no longer exists, the table fixes `pageIndex` (and emits `pageIndexChange`). Not while `loading`.
- The `index` in `(action)` and in templates (`appCell`, `appActions`) is the **position in `data`**, not on the page. Without `rowKey`, the selection also holds positions in `data`, and "select all" keeps the other pages'.

### Server (`paginate="server"`)

`data` is already the current page; pass the total in `totalItems` and fetch again when the page changes.

```html
<app-table [columns]="columns" [data]="page()" [loading]="loading()"
           paginate="server" [totalItems]="total()"
           [pageIndex]="index()" (pageIndexChange)="fetch($event)"
           [pageSize]="20" />
```

- The table slices nothing: it only emits `pageIndexChange`/`pageSizeChange`. While the new page loads, use `loading` (skeleton).
- Sorting also goes back to the first page (emits `pageIndexChange(0)`).

### Footer

- Hidden on **error** (no pages to navigate) and without rows; with a single page, only the range shows.
- Changing rows per page keeps the first visible row on screen.
- The range is announced to screen readers (`aria-live="polite"`).
- When the table scrolls horizontally, the footer stays fully in view (the table measures the wrapper width).
- Texts: `rangeLabel`, `pageSizeLabel`, `paginationLabel`.

## Bulk actions

With `selectable` and `[bulkActions]`, a bar sits above the table. With selected rows it shows the counter ("3 selecionados"), **Limpar seleção** and the buttons. A click emits `(bulkAction)` with the selected **keys**.

Without a selection, `bulkBarIdle` decides what shows:

| `bulkBarIdle`       | Without a selection                           | When the first row is checked |
|---------------------|-----------------------------------------------|-------------------------------|
| `'space'` (default) | nothing, but the bar keeps its space          | the table does not move       |
| `'hint'`            | the `noSelectionLabel` text ("Nenhuma linha selecionada") | the table does not move |
| `'hidden'`          | nothing, and the bar takes no space           | the table moves down          |

```ts
bulkActions: TableBulkAction<string>[] = [
  { type: 'export', label: 'Export' },
  {
    type: 'delete',
    label: 'Delete selected',
    danger: true,
    disabled: docs => this.rows().some(r => docs.includes(r.documento) && r.tipo === 'Correntista'),
    disabledReason: () => 'the selection has account holders, who can only be removed by the branch',
  },
];

onBulk(e: { type: string; keys: string[] }) {
  if (e.type === 'delete') {
    this.api.delete(e.keys).subscribe(() => this.selected.set([]));
  }
}
```

```html
<app-table [data]="pagedRows()" [selectable]="true" rowKey="documento"
           [selected]="selected()" (selectedChange)="selected.set($event)"
           [bulkActions]="bulkActions" (bulkAction)="onBulk($event)" />
```

```ts
export interface TableBulkAction<K = any> {
  type: string;                 // emitted in (bulkAction)
  label: string;                // button text
  danger?: boolean;             // destructive (red)
  disabled?: (keys: K[]) => boolean;                          // stays focusable (aria-disabled)
  disabledReason?: (keys: K[]) => string | null | undefined;  // reason, in the tooltip
}
```

- **Use `rowKey`:** the selection spans pages, so the event carries **keys**, including rows that are not in `data`. Without `rowKey`, you get indices into `data`.
- **Clear the selection** (`selected`) once the action is done: the buttons go away and focus moves to "select all" (or the table) instead of falling to `<body>`.
- Unavailable action: `aria-disabled` (stays focusable, the click emits nothing) and the reason shows in the tooltip.
- The counter is announced to screen readers on every selection change. For another language, pass `selectedCountLabel`, `noSelectionLabel`, `clearSelectionLabel` and `bulkActionsLabel`.
- The bar is as wide as its content and stays in view when the wrapper scrolls horizontally (`position: sticky`).

### Sorting (controlled)

The component emits `sortChange` and sets `aria-sort` on `<th>`. Keep the sorted view in the host:

```ts
type SortState = { key: string; dir: 'asc'|'desc' };
const sort = signal<SortState|null>(null);
const collator = new Intl.Collator(undefined, { numeric:true, sensitivity:'base' });

const sortedRows = computed(() => {
  const s = sort(); if (!s) return rows;
  const k = s.key as keyof Row;
  const dir = s.dir === 'asc' ? 1 : -1;
  return [...rows].sort((a,b) => {
    const av = a[k] as any, bv = b[k] as any;
    const cmp = (typeof av === 'number' && typeof bv === 'number')
      ? av - bv
      : collator.compare(String(av ?? ''), String(bv ?? ''));
    return cmp * dir;
  });
});
```

```html
<app-table
  [columns]="columns"
  [data]="sortedRows()"
  (sortChange)="sort.set($event)">
</app-table>
```

### Loading, empty and error

```html
<app-table
  [columns]="columns"
  [data]="rows"
  [loading]="loading()"
  [loadingRows]="5"
  [emptyMessage]="'No records to display'"
  [error]="error()"
  (retry)="load()">
</app-table>
```

The table body shows one state at a time, in this order of precedence: **loading** (skeleton) > **error** > **data** > **empty**.

#### Load error

When fetching fails, pass the message in `error`. Otherwise the table would show "No records", implying there is no data when there was actually an error.

```ts
error = signal<string | null>(null);

load() {
  this.loading.set(true);
  this.api.list().subscribe({
    next: rows => { this.rows.set(rows); this.error.set(null); this.loading.set(false); },
    error: () => { this.error.set('Could not load the records.'); this.loading.set(false); },
  });
}
```

- The message replaces the rows, with an icon, and is announced to screen readers (`role="alert"`).
- **"Tentar novamente"** emits `retry`; its text comes from `retryLabel` (`null` hides the button, for errors that retrying won't fix).
- No need to clear `error` before retrying: `loading` wins, and the message only comes back if `error` is still set when `loading` ends.
- **Focus:** the button disappears while loading, so focus moves to the table; if it fails again, focus returns to the retry button. For this, set `loading` inside the `(retry)` handler (as in the example above).
- "Select all" is disabled without visible rows (loading, error or empty). Hide the pagination while there is an error.
- If the app also shows a toast for request errors, the table state is still needed: the toast goes away and the table would look empty.

## Declarative actions

```ts
export type ActionKind = 'edit' | 'delete' | 'view' | 'download';

export interface TableAction<T = any> {
  kind: ActionKind;
  label?: string;                       // short name (tooltip and screen reader); defaults to `labels.table.action[kind]` (English: Edit, Delete...)
  ariaLabel?: string;                   // more specific name (e.g. "Edit Ana"); wins over label
  iconUrl?: string;                     // optional external icon (e.g. /icons/svg/pen-box.svg)
  visible?: (row: T, index: number) => boolean;
  disabled?: (row: T, index: number) => boolean;  // stays focusable (aria-disabled)
  disabledReason?: (row: T, index: number) => string | null | undefined; // shown in the tooltip
}
```

If you pass `[actions]`, the component auto-renders an action list **unless** you provide an `appActions` slot (which overrides the default). Inline SVGs inherit `currentColor`; `iconUrl` works with external assets.

### Tooltip and unavailable actions

Each action button shows its name in a tooltip ([`appTooltip`](../tooltip/tooltip.en.md)), so mouse users also see what an icon does. The name is `ariaLabel`, then `label`, then the default for the `kind` (`Editar`, `Excluir`, `Visualizar`, `Baixar`); pass `label` to translate it.

A disabled action uses `aria-disabled` instead of `disabled`: it stays focusable, the click is ignored (no `action` event) and, with `disabledReason`, the tooltip explains why:

```ts
actions: TableAction<Row>[] = [
  { kind: 'edit', label: 'Edit' },
  {
    kind: 'delete',
    label: 'Delete',
    disabled: row => row.tipo === 'Correntista',
    disabledReason: () => 'account holders can only be removed by the branch',
  }, // → "Delete (account holders can only be removed by the branch)"
  { kind: 'download', visible: row => row.hasContract },
];
```

## Accessibility
- Semantic `<table>`, sticky `<thead>`, labeled checkboxes (`aria-label`).
- Visible focus on action buttons (`:focus-visible`).
- Error state: announced message (`role="alert"`), `aria-busy` on the table while loading, and focus is not lost on retry.
- Collapsed columns: "Mostrar detalhes" button with `aria-expanded` and `aria-controls` pointing to the details row; the button column has a name (`detailsLabel`).
- Bulk actions: bar with `role="group"` and a name (`bulkActionsLabel`), announced counter (`aria-live="polite"`), and focus moves to "select all" when the buttons go away.
- Declarative actions: the name is also a tooltip; unavailable actions use `aria-disabled` (focusable, with the reason) and the actions column header has a screen-reader name (`actionsLabel`).
- Avoid global resets like `button { border: none !important; ... }` — scope styles to `.icon-btn` instead.
- Clickable header with `aria-sort="ascending|descending|none"` and visible focus on the `th` (Enter/Space toggles).

## Troubleshooting
- **Asset 404**: if using `public/` assets, put your SVG at `public/icons/...` and reference as `/icons/...`. If you prefer `src/assets`, ensure it’s listed under `assets` in `angular.json` and reference as `/assets/...`.
- **Selection with sorting/pagination**: without `rowKey`, `selected` holds indices into `data`, which shift when you sort or paginate outside the table. Pass `rowKey` to select by key:
  ```html
  <app-table [data]="pagedRows()" [selectable]="true" rowKey="documento"
             [selected]="selected()" (selectedChange)="selected.set($event)">
  </app-table>
  ```
  “Select all” toggles only the visible rows and keeps selections from other pages.

## Responsiveness

### 1) Desktop / Horizontal wrap
Wrap the table with a `.tbl-wrap` container to allow horizontal scrolling when columns overflow. The container adds **edge shadows** to hint overflow:

```html
<div class="tbl-wrap">
  <app-table [columns]="columns" [data]="rows"></app-table>
</div>
```

The demo Sass ships those gradients and the rounded corners.

With `priority` on columns, the table hides columns instead of scrolling (see **Collapsible columns**).

### 2) Mobile / “Stack layout” (≤ 640px)
Below `640px`, each `<tr>` becomes a card-like block and each `<td>` shows its column label using the `data-label` attribute.  
The **select** column moves to the top of the card and **actions** go to the bottom, right-aligned.

> Tip: make sure each cell has `data-label` (the component auto-sets it from `ColumnDef.header`).

## Select column width

By default, the select column uses `--tbl-select-w: 44px` (48px in the demo). Tweak it via **CSS token**:

```sass
/* in your page or card wrapper */
.wrapper
  --tbl-select-w: 40px
```

> Optionally, you may expose an `@Input() selectColWidth` if you added that extension to the component.

## Accessibility (sorting)
Clickable headers keep `aria-sort="ascending|descending|none"` and support keyboard (Enter/Space). The component emits `sortChange`; keep the sorted view in the host. See “Sorting (controlled)”.
